The block format

Where it lives and what the plugin keeps.

Paste this template after your designer prose (a blank line between them). Keys are flat key: value lines; lines starting with # are comments. The Config tab writes the same block for you and keeps your prose.

compose-studio: # role: button | card | fab | slider | switch | checkbox | chip | # input | progress | badge | avatar | divider | listitem # kind: icon | image | vector # assets: auto | export | code # implementation: auto | custom # mapping: MyAppButton # mappingArgs: label="Sign In", count=int:2, delay=long:1, opacity=float:0.5, padding=dp:16, icon=@icon # note: copied into the generated file as a comment role: card

Prose above the marker is preserved verbatim on every rewrite, and comments inside the block survive the raw/advanced editor. Description edits made in Figma’s own info panel may lag until the component is re-published.

Material 3 implementation

When generated code is the real Material composable.

For card, button and fab with Implementation: auto, the plugin emits the Material composable only when the design’s look can be reproduced exactly: a single solid fill, no border/shadow/extra backgrounds, any radius with clip on, and — for fab — a circular shape. Children then sit directly in the Material content lambda; the look comes from colors/shape arguments instead of painted frames. Otherwise the plugin emits the custom body (same visual, plus the role parameters) and reports why.

Assets: kind & policy

Make a component an asset — or force it to stay code.
kind
an explicit asset qualification — icon / image / vector — replacing any name-prefix rule; every instance exports as that asset type and no code is generated
assets: export
always export this component as an asset (never code)
assets: code
always generate code — wins over kind and over any global asset detection
assets: auto
name prefixes and other rules decide (default)

Precedence: ignore marks > profile component mappings > the block’s mapping > its kind/assets directive > curated library > auto-detection. With a mapping set, role/asset directives are ignored for generation (the mapped call replaces them) — clear the mapping to use them.

Mapping to your own composable

Instances call your app’s composable instead of generated code.

mapping is a Kotlin symbol (simple or fully qualified). mappingArgs fills the target composable’s parameters — recursion walks the instance subtree: the first text becomes the string, an icon/vector child becomes the icon asset, a solid color becomes its hex, text-node children become @content slots, and the root’s modifier slot becomes @modifier. Quoted values are constants, and true/42 are Kotlin literals.

mapping: com.example.ui.MyButton mappingArgs: title=string:"Sign In", icon=@icon, maxLines=int:2, ratio=double:0.5, padding=dp:16, tint=color:8080FF, style=object:TextStyle.Default

Mapping sources: @text first text · @icon icon · @color color · @content text slot · @modifier modifier. Typed constants: @int · @long (adds L) · @float (adds f) · @double · @boolean · @string (quoted) · @char · @dp (16.dp) · @sp (14.sp) · @color hex → Color(0x…) · @object raw Kotlin expression. Untyped values (42, "quoted", raw expressions) still work.

Why do I see “mixed”?

Selecting several components together.

When the selected components disagree on a field, that control shows multiple values instead of a value. Leave it as-is to keep each component’s own setting, or pick a value once to override it on all selected components when you press Apply. Unedited fields keep their per-component values too.

Presets

Save and reuse configurations.

Built-in starters (★) — Material Button / Card / Fab, icon and image assets, and an all-defaults reset — are always in the dropdown as starting points; they cannot be deleted, but saving your own preset under the same name replaces one. Save current… captures exactly what the editor shows (mixed fields keep each component’s own, though a preset stores one merged value — edit what you want, press Apply first if needed). Loading a preset fills every field of the editor; nothing reaches a component until Apply. Presets live in this Figma client’s storage, up to 30, newer saves replacing the oldest ones. The editor also auto-fills the Mapping with a Kotlin function name derived from the component’s name whenever no mapping is set — clear it or type your own before Apply.

Decide what becomes what. Curate which layers turn into assets, which into layout, and which get ignored (e.g. the phone status bar). Everything here is remembered between sessions and applies to every future conversion.

Asset name filters

Only layers named with the prefix become assets — everything else stays plain layout.

Icon filter: only vectors whose name starts with it export as SVG and render as Image(painterResource(...)). Example: icon_star → drawable ic_star.

Image filter: same idea for PNG image fills (→ drawable-nodpi). Example: img_banner stays drawable img_banner.

Ignore rules

Status bars, watermarks, helper frames — hidden from every conversion (layout and assets).

Any layer whose name starts with this — and its whole subtree — is skipped. Case-insensitive.
